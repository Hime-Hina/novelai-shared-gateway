# 提交后状态通知（R01）

当前单进程网关在 SQLite 成功提交并更新缓存后通知页面，连续变更按
200 毫秒合并；持续写入时，从首个变更起最多等待一秒开始发送。数据库
排队、Discord 资格核验和网络耗时不包含在这个合并上限内。

## 提交与授权

存储层复用标准库 EventEmitter 和既有实际变更比较，覆盖普通、dirty-row、
延期 flush、整库替换、冷历史清理及图片裁剪。回滚、尚未 flush、没有实际
变化的鉴权、单纯签发会话、幂等别名和终态凭据归档均不广播。监听器失败
不改变已提交结果，也不阻止其他订阅者；关闭存储时清理订阅和定时器。

内部通知仅含集合名、稳定成员 ID、任务变化的成员/日期配对和是否影响全员；不传原始行、提示词、
Key 或会话摘要。任务归属优先取父请求，其次尝试记录，旧 token 仅在服务
内部匹配；冷删除在删除前确定归属。无法确定归属时保守扩大失效范围，
并不扩大后续查询权限。

`GET /api/member/shared-events` 保留原 `shared-status`，增加
`state-invalidated`，基础正文保持五个字段：

```json
{"bootId":"本次写入服务启动标识","version":12,"scopes":["shared","member"],"updatedAt":"2026-10-17T00:00:00.000Z","resync":false}
```

U03 在任务统计投影改变时增加可选 `activityDates:["2026-10-17"]`。日期按
台北提交日计算，限定最近一年；普通成员仅收到自己的日期，owner 可收到全局
日期，归属未知的日期只给 owner。合并仍保留成员与日期配对，不能把成员集合
与日期集合交叉广播。单纯更新时间、图片引用和普通资料变化不触发日期重算。
浏览器合并这些日期并查询日桶；首次/重连、跨台北日或断连后的可见兜底才
重新校准全年。历史清理的空增量会移除旧桶，说明见[调用热力图](call-heatmap.md)。

shared 表示公共概览，member 仅通知本人或确实受影响的全员，owner 只向
重新鉴权后的 owner 发送。成员 ID 不进入 SSE。会话删除只唤醒鉴权，失效
发送 auth-expired；不会因此刷新全站。原每成员三连接、总计一百连接、
背压断开、十五秒心跳及每两秒时间/权限边界检查保留。

版本在合并发出时递增；授权过滤与合并允许跳号，不要求“上一号加一”。
每次连接建立都以 resync 要求读取当前授权快照，包括客户端带旧
Last-Event-ID 的重连。没有事件历史或重放队列；重启换 bootId。处理
异步鉴权期间发生的新变更时，当前连接会合并补发，不并发执行多次检查。

## 查询与页面

成员 me、管理成员摘要、Bearer 个人额度 GET 在 settings 副本与 ledger
副本上估算自然恢复，不再把读取变成账本提交。实际官方余额同步、派发、
结算和管理操作继续在原写事务中同步额度、保留审计，避免“通知→查询→
再写入→再通知”的反馈循环。

成员和 owner 页共用连接生命周期。隐藏或离开页面关闭连接，恢复可见后
重新连接并校准；重复版本忽略，新 boot 或 resync 重读。临时网络/Discord
故障保留旧视图和断线提示，永久关闭而未确认鉴权失效时五秒后重连。
可见页面每三十秒低频读取本地估算，补充没有事务的自然恢复。

个人通知刷新额度和任务，保留打开的批次、已展示的本人 Key；查询进行中
的多次通知只补读一次。owner 的 shared 更新直接更新概览，owner 失效才
读取管理摘要及当前可见内容。分组、告警、PST、账务输入和对话框不被
后台响应覆盖；调额沿用打开表单时的配置版本。会话失效清空秘密展示，
旧请求不能重新打开已关闭的登录视图。
