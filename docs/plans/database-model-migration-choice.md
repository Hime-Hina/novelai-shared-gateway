| 已知历史输入          | 可读取、领取已存附件并显式复制给用户编辑；缺首次定义仍不宣称原派发可恢复                                                      | 相同；新生成经用户提交完整新意图和当前报价确认，不把复制当作原 POST 等价                                                                 |

推荐 **B，并保留表中所列在线历史、原请求、原图及已知输入能力**。现有证据未证明 A 不可行；推荐原因是 A 额外需要一套严格区分历史未知与在线许可的导入合同及 16,509 个原提交的逐笔核对，而新服务并不需要常态运行旧解释器。B 将这部分原始审计交给固定离线归档，能够让新在线契约保持单一；它不缩短 D8 留存，也不删除任何历史或权益。

开发耗时和最终维护窗口尚不能用盘点时间替代。选定后只实现一条路线，先完成一份真实困难切片，再做完整副本转换、重放/私有/对象恢复及容量测量；若切片不能满足所选范围，再提交具体差异，不悄悄扩第二套迁移器。

## 需要一起固定的产品规则

1. **不可证明的 13 个旧键：** 建议相同键的 POST 返回 409 和稳定的“原意图无法验证”原因，附原请求/结果查询入口；不再执行。可证明的 27 个继续精确比较原意图并返回原回执。迁移旧键先于受理新意图，不轮换成员 ID 或清空命名空间。此为建议，待维护者确认后同步 API 契约。
2. **D6 会话：** 建议保留切点仍有效的当前会话、原期限及当前认证代次；已撤销、过期、停用或移除成员绝不恢复。若选择统一登出，则只迁移必要身份/凭据并明确撤销全部旧会话，不延长会话期限。
3. **D4：** 本副本未兑卡密和官方直连持久产物为零；最终切点必须再核对。出现新责任时逐项迁入明确等价权益或取得处置决定，不能凭本次零计数删除；易失官方队列须停接单后另核验。

## 转换及切换条件

保留原库、匹配输入/对象清单、受保护环境及解密材料；封存历史不进入七份轮换。固定旧只读工具已完成 Windows 实包复审，Linux 实包 CI 正在验收，尚不称独立归档恢复完成。新库只能由正式验证安装入口变为 ready，不能手改标记。最终须同一发布候选完成真实 HTTP/调度、重启/故障、事件和私有联合恢复、完整迁移核对、数据库/备份/外部存储容量性能，再准备最终操作单申请生产执行授权。
