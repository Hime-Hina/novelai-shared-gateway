#### 录制响应回放

增加 `--replay-dir <受保护目录>` 后，不再返回占位图片。目录内必须同时提供
`zip`、`msgpack`、`sse` 三组 `<名称>.response.bin` 与 `<名称>.replay.json`。
普通生图选择 zip；流式请求的 `parameters.stream=sse` 选择 sse，其余选择 msgpack。
回放不解释或重新编码响应正文，保留录制的 HTTP 状态、Content-Type、完整字节及
分块到达时间；网络仍可能合并传输块，不承诺重现原 TCP 分包。

元数据字段为 `version: 1`、`status`、`contentType`、`headersAtMs`、`completeAtMs`
及 `chunks: [{end, atMs}]`。`end` 是累计字节位置，时间从原始生成 POST 发出起算。
启动时校验完整单调的字节/时间范围，响应正文最多 16 MiB，元数据最多 1 MiB，
最多 4096 块。原录制耗时加 `--delay-ms` 的额外延迟不能超过 60 秒，保证仍落在
已有服务退出宽限内；断开连接会终止本次回放等待。录制正文和元数据只作为私有
运行时夹具，不提交仓库，也不让 mock 读取业务库或 OAuth/NAI 凭据。
