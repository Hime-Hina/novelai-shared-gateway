## 配置边界

- 正式 executor 复用 `novelai-gateway.service` 与 `nai-gateway` 用户，监听回环 18082；
  数据目录继续为 `/var/lib/novelai-shared-gateway`。不重新 bootstrap，不导入测试库。
- Nuxt 使用独立 `novelai-gateway-web.service`、无登录用户 `nai-gateway-web`，监听原入口
  18081；仅允许回环联网，禁止读取生产数据库、旧业务配置和 executor 配置。
- executor 先读取原 `gateway.env`，后读取仅含运行参数和新内部密钥的 `executor.env`。
  原 OAuth 应用、owner、管理员密钥和上游设置保留；web.env 只含网页运行参数与内部密钥。
  两份新 env 均为 root:root 0600，不把真实值写入仓库或验收报告。
- 可信代理为同机 cloudflared → Nuxt → executor 的回环地址。公网只能通过 Tunnel 到网页，
  不开放 18082。executor 需要访问真实 NAI、Discord，不能携带测试版禁网/mock 配置。
- 两服务不使用 Requires/PartOf 联动停止。停止网页不会停止已持久受理的生成。
  测试服务继续 disabled，不启用开机启动；正式服务的启用安排在获准切换时执行。

模板位于 `deploy/systemd/novelai-gateway{,-web}.service` 及
`deploy/production-{executor,web}.env.example`。准备阶段只保存和校验文件，不覆盖
`/etc/systemd/system/novelai-gateway.service`，不改变生产 current、端口或隧道路由。

## 获准后的切换顺序

1. 再核验候选哈希、配置权限、磁盘、18082 空闲及唯一生产写入者，确认备份可读取。
2. 从 Cloudflare 控制面保存最新完整配置，仅将 `nai.himehina.space` 的规则临时改为
   `http_status:503`。其他域名与测试入口保留，不停止共享 cloudflared。
3. 旧版没有可靠的停止接单开关。入口拒绝新请求后，等待其 queued/pending/running
   全部归零，再正常停止旧服务；异常在途未确认时不强杀。确认旧 PID 退出和端口释放。
4. 制作停机后一致性完整备份并保留为 cutover 备份，保存原 unit、配置、程序和 Node。
   此时重新读取数据数量及余额基线，不能沿用测试副本或此前快照的数量。
5. 安装已准备的新 env 和两份 unit，设置生产 current 指向候选，daemon-reload。
   先启动唯一 executor，再启动网页；维护入口保持关闭。
6. 验证数据库完整性、成员/任务/图片/账本数量、余额、内部鉴权、原图读取和正式 OAuth
   配置。恢复原生产路由后验证登录、SSE 与读取；空闲时经唯一调度器做免费 V4.5 烟测。

首次迁移会丢失旧程序仅存在内存中的网页会话，需要重新登录；成员 API Key 和余额保留。
维护窗口无法消除，不能同时启动新旧两个生产调度器。
