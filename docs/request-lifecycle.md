# 持久请求与排队生命周期（F06-1 / F06-2a）

F06-1 只接入网页 `POST /api/jobs` 单图路径，包括已有的明确缓存命中。
Native、direct、OpenAI 仍走原路径；多图 pending、公平激活、可选幂等与
同步连接解耦将在后续片接入，不能将本片视为 F06 全部完成。

网页请求受理时，在同一个同步 SQLite 事务中写入不可变
`generation_requests` 父记录、`jobs` 子记录和原有账本。任一 SQL 写入
失败，父记录、任务和账本一起回滚。父记录保存稳定成员 ID、来源、操作、
提交时间、完整规范化参数及 UTF-8 字节数，不保存 API Key 或原始 URL。

父表不加入 JsonStore 的通用集合。历史参数留在 SQLite；热 job 只保留
requestId、模型、尺寸、步数、种子等小字段，不复制 tag、完整提示词、
负面提示词或输入图片。执行时按 requestId 读取参数，网页单任务回包和
错误详情按需冷读取完整提示词，不截断原 API 字段。旧无 requestId 的
任务继续使用原内联参数。成员任务列表仅需要模型和状态，不读取大参数。

网页正文上限保持 **2 MiB**。规范化请求默认上限为 **32 MiB**
（`REQUEST_MAX_PAYLOAD_BYTES`），新路径的全局活动载荷默认 **64 MiB**
（`QUEUE_MAX_PAYLOAD_BYTES`）。计数包含 base64 等字符串的 UTF-8 字节；
它不是解码图片的大小，也不是 JavaScript 字符数。两个限制可以下调验证。

路由先规范化路径，再在读正文前创建临时字节占用。每个正文 chunk 都在
保留和拼接前检查总预算；规范化后的参数按实际序列化字节重新校验。
提交成功后，在下一项串行受理开始前移交为持久活动字节；解析失败、断线
和写入失败由 HTTP finally 释放临时占用。没有通用提交回调机制。

持久占用从小型活动 jobs 索引取去重 requestId，再按父表主键求和，不扫
所有历史父记录、不加载 payload。当前活动状态为 queued/running；后续
接入 pending 时必须同时扩展活动索引、查询和准入计数。运行中仍占用预算；
成功、失败或未派发取消随子状态提交后释放。完成后只释放预算，父参数和
结果仍保留。显式全库替换才在同一事务移除已无任务引用的父记录。

本片的 32/64 MiB 初值来自 Windows 合成实验，不是 bob 上的内存保证。
其它尚未迁移入口和图片解码/结果缓冲不能据此声称已获得全局内存上界。
后续各入口迁移还必须避免 HTTP handler 在等待结果时保留完整大参数。

首片验证包含 SQLite 写入失败回滚、并发受理正好占满字节预算、活动查询
EXPLAIN、历史参数不进入热缓存，以及真实 HTTP 的大提示词/断线/解析失败/
路径规范化和重启恢复。Linux 测试镜像另外在 UID 1000、断网、只读根目录
加临时可写数据卷下验证了五次迁移、父子同事务写入、冷读取、重开后字节
占用、终态释放与历史保留、SQLite integrity 和 HTTP 启动；没有请求 NAI。
Linux 检查验证功能与权限，内存峰值证据仍仅来自 Windows 合成实验。

后续 Native 与连接解耦片还需覆盖执行尝试的实际存活期：timeout/cleanup
可能先把 job 标记 failed，但执行器仍持有输入或等待迟到响应。届时预算
必须把尚未 finish 的尝试计入并与 SQL 活动任务去重，不能仅看 job 状态
提前释放；进程重启则按原执行进程已消失及未知消费证据恢复，不重发原尝试。

## 已接入的持久排队序号子片

网页、direct、OpenAI、Native 当前实际创建的每个 queued 任务均分配独立
`queueSeq`；缓存命中直接完成的记录不占号。SQLite 任务影子列与
`app_meta.queue_sequence` 最高号在原有同一个同步事务提交，写失败一起
回滚；最高号不随历史任务清理或重启归零。

旧活任务首次启动时按原调度实际使用的已加载任务数组过滤后 `reverse`
顺序编号。这包括历史排序值并列时原活动索引枚举的影响，不改写原
`order_value`，也不假定创建时间天然等同旧队列顺序。此后派发直接读取
queued 部分索引并按 `queue_seq` 排序，公开排队进度使用同一序号。

这一子片立即用于现有请求路径；Native 全批次受理与 pending 激活仍由
下一片接入。旧版本没有持久化的剩余图片意图仍无法凭空恢复。

F06-2a 的真实 HTTP 验证包含 direct 原图片响应、各入口派发前已有序号，
以及故意反转历史排序后重启仍按 queueSeq 执行。存储测试分别在任务写入
和最高号写入时注入 SQLite 失败，确认二者一起回滚。Linux 新镜像在同样的
UID 1000、断网、只读根目录条件下验证六次迁移、旧 queued 初始化、SQL
派发顺序、终态后序号继续递增、父参数/预算保留规则及 HTTP 启动。
